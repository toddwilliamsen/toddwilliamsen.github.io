Rocky Lab Platform

Custom Rocky Linux 9.7 images built from scratch, provisioned with ARM, and governed so developer labs are fast to create and hard to leave wide open.

Security & cloud·Azure labs · images · IaC

This is the lab platform work: secure-by-default environments for developers to deploy, exercise, and tear down—without waiting on a ticket that takes longer than the experiment.

The problem

Ad-hoc lab VMs accumulate drift: missing agents, weak baselines, public endpoints “just for testing,” and no shared identity or policy story. Security reviews become archaeology. Developers wait hours for something that should take minutes.

What we built

1. Rocky Linux 9.7 images from scratch

Custom images—not a lightly edited marketplace default—built so every lab VM starts from a known baseline:

  • Rocky Linux 9.7 as the guest OS
  • Python and PowerShell Core embedded for automation parity with the rest of the cloud toolchain
  • Hardened configuration baselines baked into the image
  • Cloud agents included so management and monitoring are not optional afterthoughts

2. ARM-based provisioning

Automated VM lifecycle with custom ARM templates: image reference, networking, identity bindings, and policy enforcement at deploy time. The point is convergence—redeploy gets the same shape— not a one-off portal click trail.

3. Lab management application

A Python lab management app on Azure Web Apps so developers can deploy, manage, and destroy isolated lab environments on demand. Provisioning time dropped from hours to minutes by automating the full VM lifecycle.

4. Governance and CSPM

  • Azure Policy and RBAC guardrails for lab subscriptions / resource groups
  • Defender for Cloud / CSPM aligned to NIST 800-53 and CIS benchmarks
  • Cloud economics and right-sizing so labs do not quietly become a second production bill

Lessons learned

  • Image > after-the-fact hardening. If SSH policy, agents, and packages are negotiated per VM, you will lose.
  • Template + policy beat wiki. Networking and identity bindings belong in ARM; deny/deploy policies catch drift.
  • Self-service needs a destroy path. Labs without teardown become unowned infrastructure.
  • Measure time-to-lab. “Secure” that takes all afternoon loses to insecure that takes ten minutes—unless secure is also fast.
